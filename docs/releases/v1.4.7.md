# Quest APK Renamer 1.4.7

Version 1.4.7 is a bug-fix release for two real-world bundles that 1.4.6 handled wrongly.

## Renamed apps with native code launch again

Earlier versions renamed the game's Java classes along with the package ID
(`cn.vr4p.player.Main4XActivity` became `cn.dev.vr4p.player.Main4XActivity`). Any app whose
native libraries bind to those classes — `Java_cn_vr4p_player_Main4XActivity_*` exports and
`FindClass("cn/vr4p/player/Main4XActivity")` lookups — then crashed at launch, because the
`.so` files still looked for the old names.

The rewrite now changes only the **application ID**: the manifest `package`, content-provider
authorities, custom permissions, intent actions, and identity strings in code and resources.
Every Java class name and descriptor stays exactly as it was, relative component names in the
manifest are expanded against the original package so they still point at those classes, and
layout class names, `R` references, and reflection strings are left alone. The renamed copy still
installs beside the original with its own data.

Reports and the Inspector now show *application-ID references changed* and *Java class references
kept* separately, and scanning a 400 MB decode takes under a second instead of half a minute.

## Tag-less patch OBBs

Some releases ship `patch.<package>.obb` without a version tag next to the usual
`main.<version>.<package>.obb`. Those bundles were rejected as "unsupported files"; they are now
recognized, renamed (`patch.<new-package>.obb`), installed, and pruned like any other expansion
file.

Use the tool only with APK/OBB bundles you own or are authorized to modify.
